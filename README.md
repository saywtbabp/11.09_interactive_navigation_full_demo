# 一致性交互导航：玻璃、门与导向箱完整演示

这是独立的新工程。保留10.31的柔性无人机、旋翼控制、MuJoCo外观、RGB/测距融合、认知地图与玻璃验证；门和箱子使用11.08的数据约束、连续权重和多数规则。已确认可穿越时，卸载直接朝安全通行连接点制动、调整姿态，安全状态满足后接续穿越；选择绕行时保留就近恢复。原10.31、11.08目录没有修改。

当前默认是**局部路线比较、巡航观测、脱开滑行跟踪、连续制动转向、通行完成后冻结推断**。最新回放直接打开根目录`report.html`，原始结果在`results/a01_probe_then_bypass`。P01交互后穿门，A01先续推、后经F04绕行，箱子B01通过。S01在F01出口就被否决，直接去F02。门和箱子的脱开控制见`COAST_TRACKING.md`。

歧义开口低速验证通过后，从当前速度平滑提速，穿过出口点时继续飞行。短出口段速度参考上限为0.25 m/s，下一段巡航承接同一个速度参考，逐步恢复到0.45 m/s。报告可通过“空开口通过 F02”等按钮跳到切换时刻，并查看高度和垂直速度。

报告采用**左现场、右权重与决策分界**的同步布局：选择P01、A01或B01并“从头播放本段”，可直接观察接触、脱开与参数变化。左下新增实际速度/连续参考曲线；阶段分为接触续推、脱开滑行、制动调姿、接入通行路线和穿越。窄屏自动上下排列。第二扇门包含退出后飞往F04绕行，支持暂停/逐帧及约束带选择。详见`SITE_REPLAY.md`。

第二扇门A01的铰链惯量设为0.22 kg·m²，摩擦力矩设为1.296 N·m。选择A01回放后，点“支持续推”和“决定绕行”可直接比较切换前后的权重、分界和无人机位置。

成功运行后，双击`open_latest_report.cmd`可打开本地最新回放。`results/` 和根目录的 `report.html` 由运行生成，并在 Git 中忽略。设计文档提到的旧回放和一次性检查留在原工程目录。

## 直接运行

1. PyCharm打开本目录。
2. 选择已有Conda解释器：`G:\anaconda3\envs\mujoco\python.exe`。
3. 如果是从 Git 新检出的目录，在项目根目录执行下方命令，将视觉依赖安装到项目的 `.vendor`。原有工程已经有 `.vendor` 时可直接运行。
4. 在 PyCharm 运行根目录的 **main.py**。

```powershell
& 'G:\anaconda3\envs\mujoco\python.exe' -m pip install --target .vendor -r requirements-vision-runtime.txt
```

仓库随附三类识别的 ONNX 权重、校验元数据和 Windows 规划器 `fast_grid.dll`。可选的训练脚本使用一份初始化权重和固定的合成场景布局，训练图像与标签可用 `tools/generate_vision.py` 重新生成。

也可双击`run_demo.cmd`。图形窗口默认2倍速；运算速度取决于机器性能，速度选择不会改变物理步长或决策。

```powershell
& 'G:\anaconda3\envs\mujoco\python.exe' main.py
& 'G:\anaconda3\envs\mujoco\python.exe' main.py --headless --output results/my_run
& 'G:\anaconda3\envs\mujoco\python.exe' main.py --decision-mode after-probe
& 'G:\anaconda3\envs\mujoco\python.exe' replay_report.py results/my_run
```

每次运行生成独立结果目录，含`report.html`、`summary.json`、`replay.json`、`decisions.json`、`sensors.jsonl`、在线地图、视觉/玻璃验证日志、每个交互物的完整窗口/权重快照和现场图片。成功运行还会更新根目录`report.html`，供`open_latest_report.cmd`打开；单独重建历史报告不会覆盖根目录最新版。HTML内嵌数据、图像和参数回放，可断网打开。工程入口只使用根目录`mission.py`和`session.py`；`navigation/mission.py`等保留的旧模块属于来源参考。

## 门和箱子决策流程

1. 只规划到当前隔墙后约2米的共同局部汇合点，局部网格不包含更远的路线代价。最终目的地只在最后无交互路段使用。当前行已有可靠类别的候选先比较成本，再选择实际飞行路线。
2. 在当前位置比较`G0 = L_bypass - L_optimistic`与`额外接近距离 + λ Fcap Δs_probe`，两条路线均到同一个局部点；否决就直接绕行。接近途中刚获得可靠识别时，边巡航边比较，不插入识别后的制动停稳。此时没有有限质量/阻力先验，`p_ok`未定义。
3. 通过门限才继续接近并试探。接触接近分两段：远处上限0.30m/s，依据制动距离平滑减速；最后约0.34m机体接触净距内使用0.055–0.15m/s。50%多数规则、误差界与地图保留；本次仅将P01铰链阻力改为0.05N·m，并补齐门临近目标时的主动制动。
4. 从有运动的0.1秒窗口提取速度增量和力冲量，统一到局部SI变量。门使用`s=r0*q, v=r0*ω, F_parallel=τ/r0`，箱使用线位移和轴向力。
5. 每个窗口产生两条参数半平面约束。全部累计求交形成白色可行区；在该区域内积累连续似然权重，不再使用1024粒子有限先验。
6. 从首次接触开始计算几何边界；每个有效0.1秒窗口更新参数时，同步重算当前状态下的边界和支持率。没有固定等待窗口数。参数区尚未闭合时显示边界，但不编造可归一化概率。
7. 每次新窗口提交前先检查当前测得几何能否给出释放及目标开口通行路径；已具备则结束推断，冻结完成前最后一次真实权重与边界，不再计算“继续推”的F*=0。尚未完成时仍逐窗判断，`p_ok>0.5`续推，不支持则当次停止推压。
8. 冻结后传感器仍记录；从当前测得几何中选可接入通行路线的连接点，同时卸载、制动和调整姿态，取消中间悬停锚点及其后的独立补接。连接段检查姿态扫掠包络、墙框和门/箱运动余量。连接点保持固定；若对象继续运动让原先必须后退的连接变得保守，只在重新认证且向前改善至少0.10m时升级目标；失效则重新选择。脱离接触、速度/姿态、净空和最新通行路径连续通过0.25秒才接续穿越。图中明确标注历史冻结时间，已移动的对象始终保留为规划障碍。

- 空格暂停，R固定总览，F跟随无人机，鼠标旋转/缩放，S保存当前四视图，V打开全部模型传感器/控制通道窗口。
- 下方显示当前曝光对应的真实RGB/检测框、SI力/速度曲线和该物体独立的参数图。
- 参数图：白框是累计约束交集；蓝紫线是原始约束带；浅灰叉表示已排除候选、有效权重为0；绿/橙是续推/绕行侧，亮度表示相对权重。

## 测量范围，请据此解释结果

在线早决策改变了动作和后续观测，不能保证复现旧版53.68%/40.72%的支持率。本次按要求只调整P01铰链阻力，形成穿门与绕行的对照；其余物体参数、地图、误差尺度和50%门限保留。接触中代价比较“保持接触续推”与“卸载退出”，不能继续沿用停稳后再接触的代价。旧“临界门”布局在新动作下可能不再接近50%。

本版完整接通实际渲染RGB、ONNX检测、匿名含噪测距、原玻璃验证与物理飞行。门/箱的力学推断沿用11.08 **MuJoCo关节位姿/速度、接触力参考测量**；无人机定位也使用仿真参考本体状态。没有宣称门/箱已具备实机视觉测速、飞控接触力精度或完整在线不确定度传播。

当前`belief.py`保留11.08工程误差尺度：`ε_Δv=0.025 m/s`，`ε_Y=0.025+0.10|Δs| N·s`，似然尺度`σ=ε_Y/2`。这些是当前仿真的模型/误差设置，不是由本次RGB训练或飞控位置误差自动标定的实机误差。后续接测量模型+协方差传播，应在每个窗口替换这两项，同时保留本演示的决策/可视化链路。`p_ok`是该局部模型和尺度下的权重支持率，不是实机成功率。

箱子采用一自由度地面滑动模型，未包含任意平移+旋转+倾覆。门采用已知转轴几何；与之前讨论一致，先保留视觉可识别门/箱的假设。

`Fcap=2.2N`是水平控制指令限幅，不等于真实碰撞力峰值；玻璃保持原验证算法，碰撞瞬时峰值可能高于它。日志与报告分别列出控制上限、实测/参考接触峰值和非预期墙/门框接触。

## 文件与复现

- `mission.py`：同一个World中的连续导航、感知、全局记忆与日志。
- `local_navigation.py`：共同局部汇合点、局部规划区域、无航点停稳的巡航及移动观测。
- `passage_completion.py`：当前几何通行证书、结束推断、冻结最后真实权重与边界。
- `passage_transition.py`：朝通行连接点卸载、制动及姿态恢复，当前几何重新验证与安全状态交接。
- `contact_tracking.py / motion_reference.py`：脱开滞回判断、滑行/受限重新接触、从当前速度及姿态建立连续速度/加速度/航向参考。
- `site_replay.py`：根据已记录位姿绘制连续现场和阶段轨迹；两门/箱子独立播放范围包含实际绕行飞行。
- `session.py`：每个门/箱独立11.08交互会话，无重置世界。
- `online_contact.py / contact_boundary.py`：逐窗证据提交、接触中边界、立即动作切换。
- `navigation/fast_cost.py / native/fast_grid.*`：当前几何的快速网格代价计算。随包DLL只依赖Windows系统库，无需改Conda或安装SciPy；C++源码及可选重建脚本一并提供。
- `interaction_engine.py / belief.py / local_hover.py`：11.08动作、参数推断与局部恢复。
- `navigation/verification.py`：10.31玻璃/歧义开口验证，保留原逻辑。
- `navigation/vision.py / perception.py`：真实RGB三类识别与几何关联。
- `config/architecture.json`：公开几何；`config/scene.json`：物理场景真值，只交给世界构建器。
- `tools/generate_vision.py / train_vision.py`：可选离线数据与训练代码；运行演示不训练。
- `tools/tune_interaction.py / design_geometry.py`：离线场景设计工具，可恢复检查点；主程序从不恢复这些检查点。
- `tools/validate_run.py`：从完整运行日志检查效果、决策依据、动作时序和参数约束。

三类YOLO在750张独立随机合成图像上训练/验证/测试（按场景划分550/100/100），24轮；独立合成测试mAP50约0.991，**不代表实景指标**。模型元数据、SHA256和测试指标见`models/vision/metadata.json`。ONNX运行库隔离在`.vendor`，未修改原Conda环境。可选训练使用机器上已有训练环境；依赖路径通过参数指定。Ultralytics模型继承其AGPL许可条件。
